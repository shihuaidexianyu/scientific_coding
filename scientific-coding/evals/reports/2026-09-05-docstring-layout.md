# 2026-09-05 固定函数文档版式与文件流程图实测

本轮只评测用户新确认的说明版式：简短摘要之后依次为“参数、返回、处理过程、副作用”；参数和每个返回成员以名称、类型独立成行，说明另起缩进行，成员间空行；字典字段逐项列出；处理过程逐条编号。源码文件头使用开三引号独占一行的真实 module docstring，并用字符图解释实际输入、处理、输出及配置依赖。TOML 要求中文小节和键说明，本轮没有额外要求 TOML 也画流程图。

## 案例与独立证据

|---|---|---|

三维案例是专门构造的标准库小例子，没有使用或声称取得用户原来的 cluster 代码。独立探针另调用 3 × 1 × 3 的输入和双点基线，检查真实函数处理不同形状和基线均值；另以差值 `[0, -3, 3]` 核验返回负峰 `-3` 与并列绝对峰中的首个时刻。探针还核验输入的首个试次未变，这不等于对全部嵌套输入做了完整深比较，避免把局部检查说成完整不变性证明。

续接案例先完成第一条真实用户消息，独立确认旧产物与回归测试，再保存旧文件、在同一已审查源码中注入比较式改动和人工模块，通过 `claude --resume` 发送第二条用户消息。新案例只有首轮前提成立才注入；首轮缺交付会保留失败证据并停止该案例的续接，不把静态提示词或失败前提冒充中途修改实验。它测试会话轮次之间的追加修改，不测试单个 CLI 进程执行期间的实时抢占。

## 评分边界

版式、科学行为、说明语义和格式器执行分别记录。机械版式检查核验真实 docstring、分节顺序、独立参数和返回成员、说明缩进、成员空段、多返回拆分、字段与嵌套路径、文件头引号与字符图结构。它接受规范模板的逐行字段 bullet，也接受 `|`、`v` 的竖向流程图；没有强制字段采用与顶层接口项完全相同的两行写法。超过 100 字符的文档行仅记为便于评读的诊断，不设额外宽度门槛。

这些机械结果不证明说明正确。只读 judge 需要逐函数对照真实实现，分别判断轴顺序、嵌套字段、样本数、单位、路径、返回引用、修改行为以及流程图是否符合数据流。另根据完整轨迹提取的成功/失败工具执行记录，判断 agent 是否实际编写执行格式器、最后 clean 操作覆盖哪些源文件和 TOML；不能仅以脚本名称或模型自述判通过。缺少必要证据时记 unknown，不计作通过。
