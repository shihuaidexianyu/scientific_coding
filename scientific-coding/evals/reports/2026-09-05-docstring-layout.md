# 2026-09-05 固定函数文档版式与文件流程图实测

本轮只评测用户新确认的说明版式：简短摘要之后依次为“参数、返回、处理过程、副作用”；参数和每个返回成员以名称、类型独立成行，说明另起缩进行，成员间空行；字典字段逐项列出；处理过程逐条编号。源码文件头使用开三引号独占一行的真实 module docstring，并用字符图解释实际输入、处理、输出及配置依赖。TOML 要求中文小节和键说明，本轮没有额外要求 TOML 也画流程图。

## 评分边界

版式、科学行为、说明语义和格式器执行分别记录。机械版式检查核验真实 docstring、分节顺序、独立参数和返回成员、说明缩进、成员空段、多返回拆分、字段与嵌套路径、文件头引号与字符图结构。它接受规范模板的逐行字段 bullet，也接受 `|`、`v` 的竖向流程图；没有强制字段采用与顶层接口项完全相同的两行写法。超过 100 字符的文档行仅记为便于评读的诊断，不设额外宽度门槛。

这些机械结果不证明说明正确。只读 judge 需要逐函数对照真实实现，分别判断轴顺序、嵌套字段、样本数、单位、路径、返回引用、修改行为以及流程图是否符合数据流。另根据完整轨迹提取的成功/失败工具执行记录，判断 agent 是否实际编写执行格式器、最后 clean 操作覆盖哪些源文件和 TOML；不能仅以脚本名称或模型自述判通过。缺少必要证据时记 unknown，不计作通过。

按 actor 的真实交付而非解析器是否成功区分，57 个案例正常结束，3 个超时；正常完成的既定数值/文件保留探针为 56/57。唯一失败是 resumed rep2 改动或移除了两份旧边界结果。这个结果只覆盖现有正常值、替代形状和指定文件保留，**不代表外部输入保护、路径语义、公共签名和注释事实全部正确**；这些由下述独立审计补充。

实际独立分工共出现在 **5/60 个案例**，发出 7 次 Agent 调用、6 次有成功结果：cleanup20 一次、nested15 一次、resumed3 两轮各一次、resumed16 首轮一次，以及 nested17 两次中的第一次。nested17 第二次未返回即超时；resumed16 虽收到一次审阅结果，主任务仍超时。因此工具调用成功、完整任务交付、审阅意见准确是三件不同的事。其余 55 例未观察到 Task/Agent 调用；TaskCreate 待办操作不计分工。原始 init 暴露了能力，成功 Skill 加载也包含本批独立核验条款，不能把遗漏都归因于规则没加载。

固定语义评读先读实际源码、配置和结果，再读执行轨迹及自动分数。每份 `independent_review.md` 保存在对应案例目录，原产物和原 verdict 不改。替补 reader 曾对嵌套字段施加比封存模板更严的两行/空段要求，现已在五份报告中纠正：**每个字段的类型和解释可以在同一 bullet，连续字段不必额外空行；同型映射也可共享结构。** 临时 authoring formatter 不因缺科研函数 docstring 单独否决。真正把多个异型字段压成名单、缺类型/单位/键或用另一函数替代当前调用的完整结构，仍是实质遗漏。

预先固定的每类 rep1/5/10/15/20、共 15 份已全部评读，没有按分数换样本。**15 份均至少有一处实质说明或可读性要求遗漏，完整独立验收为 0/15**；这不表示它们版式毫无改善或缺陷同样严重。nested15 的图、当前函数返回结构、不等组数、重复基线计权、并列首索引和列表别名都说明得较完整，仍在两处把 summary 的所有数值概称微伏，错误地包括试次数；时间单位则另有秒的说明。完成实际 Agent 审阅后，这处单位总述错误仍留在最终产物中。

独立发现不限于这些机械规则：

- cleanup20 正确保持路径、外部保护和简化，格式器反例自测及实际 Agent 审阅也成立；但 TOML 将 0.5 阈值解释成接近本底噪声的排除依据，任务和数据没有该来源。实际子代理“全通过”遗漏了这项错误，不能因分工执行成立就认定科学说明准确。
- nested10 把实际 `value - baseline_mean` 写成“基线均值减去全部采样点”；nested20 说 times_s 只用于轴记录，实际还决定时间维和峰时刻，又称所有列表新建，实际 axes 复用输入列表。多份把首个最大值下标混同于最早时间，入口没有建立时间升序保证。当前输入升序且结果正确不能为这些一般性说明背书。
- resumed20 的人工模块、历史哈希、新阈值和 0.2 uV 差值都保持，但模块说本文件不读 TOML、load_trials 是纯函数，与同文件实际读盘冲突；README 仍留旧 `>=`，局部又把两次列表推导叫一次。它的 formatter 最终报 clean，实际却漏掉 if 后注释前的物理空行。
- formatter 的执行和有效性必须分开：有的把 NL token 当作注释块结束而拆开连续注释，有的逐行识别 TOML `#`，会给多行字符串的数据插入空行或误报。独立反例说明算法缺陷；当当前配置没有这种字符串时，不把潜在缺陷说成已经损坏本次配置。另有真实末次 TOML 编辑后没有重新执行格式器的覆盖遗漏。

对三种案例预选的 rep15，另复制最终产物为本地隔离快照，在源码已有的 `run(...)` 调用处查询真实 Pyright 1.1.413 hover。三份均显示四个中文章节和函数签名；cleanup/resumed 的跨函数引用使实际 hover 缺少当前返回结构，nested 的全部字段文字在场，但 Pyright 转换后 CommonMark 把源码两层字段列表压成单层 10 个 `<li>`，未保住嵌套层级。这既不是字段缺失，也不是单行 bullet 不允许。原始 JSON-RPC、UTF-16 位置、源码哈希、Markdown 和 HTML 详见[三份真实调用处 hover 核验](../results/docstring_layout_60_20260905/actual_hover/REVIEW.md)。范围是这三个调用点的语言服务及 Markdown 结构，未操作 VS Code/Pylance GUI，不扩大为 60 份均已验证显示。显式字段路径等后续方案只记录为下一轮建议，没有修改本批规则或产物。
