# 完整运行记录与交付成本估计

本轮将用户截图中的运行记录、完整日志、失败诊断、普通运行资源记录、批量索引，以及代码交付后的中文耗时估计写入 skill。保留已有来源、随机性与样本映射要求，不增加阶段审批或在数学函数内重复校验。

## 实施范围

- SKILL.md 规定每个顶层科研执行尝试共用一份记录；内部阶段只补充进度，独立启动才新建记录。完成代码后必须给出有依据的成本估计。
- execution.md 定义 stdout/stderr/堆栈、UTC 起止、真实退出状态、阶段耗时、资源口径、失败保留及并发索引；artifact.md 移除“普通记录/样本映射可选”的冲突描述。
- optimization.md 区分普通成本估计与真正的性能优化。前者适用于每次科研代码交付，后者仍须有前后端到端实测与科学等价性证据。没有校准时给复杂度和条件，不编造秒数。
- 可运行示例的 CLI 通过小型父进程捕获工作进程完整输出。每次在 executions/attempts/<编号> 保存日志、状态和来源快照，独立 index/<编号>.json 支持并发查询。科学函数保持原计算，直接 API/单元测试由其所属外层入口负责记录。
- 启动前保留本例 7 份源码；在配置读取边界保存已读原始字节后才解析，损坏 TOML 也可还原。外部输入核验后保存已有 binding，不重新核验或散列；成功产物仍使用原有 run.json/manifest 来源。

## 实际核验

本轮新增 6 项集成回归，并扩展已有暂停/外部篡改测试。成功、并发独立索引、重跑旧记录不变、180,000 字符长日志不截断、原生 stderr、孙进程继承输出、完整异常、配置读取失败、无效科学参数、损坏 TOML、无法启动进程，以及外部输入加载后下游失败均有实调用证据。

独立评读在临时副本完成成功/失败/暂停、4 路并发共 8 次运行，以及真实取消分支的探针，保留证据在 `evals/results/execution_independent_review_20260906/`。评读发现的三项缺口已局部修复并复测：发布前失败的配置/源码缺失、取消后的资源未知没有说明、下游失败时外部输入绑定缺失。取消分支通过一次性注入 KeyboardInterrupt 执行真实进程终止，未声称测试了所有终端或调度器的取消方式。

全量回归曾暴露旧评测器只从终端 stderr 查找篡改错误，与完整日志落盘的新入口不兼容；实际程序已非零退出且日志有原堆栈。现评测器只读取该次探针新建的日志，仍要求非零退出和确切完整性错误，不接受其他失败冒充篡改拒绝，也不拿旧日志充数。示例/skill 测试复制排除历史 executions。

最终全量 112 项回归通过（12.2 秒），仓库 linter 为 0 错误、0 警告。格式脚本覆盖本次 7 个 Python/TOML 文件，实际检查 0 处待改，并验证 docstring 后物理空行、连续块、Python/TOML 多行字符串、解析含义与幂等性。JSON 模板可解析，skill 结构验证及 git diff --check 通过。

## 本机成本校准

在隔离副本上保留默认每组 40 个试次，实际两组合计保留 N=80，分别取 B=200/2,000/20,000，每种连续运行三次。每次创建新 Python 工作进程，单个科学 worker，无 GPU。环境为 Windows 11、Python 3.14.6、Intel64 Family 6 Model 183、32 个逻辑 CPU；连续运行的文件缓存可能已热。

| B | 三次完整 CLI 墙钟范围（秒） | CLI 中位数（秒） | 分析阶段中位数（秒） |
|---:|---:|---:|---:|
| 200 | 0.346–0.431 | 0.365 | 0.039 |
| 2,000 | 0.427–0.443 | 0.430 | 0.067 |
| 20,000 | 0.643–0.684 | 0.681 | 0.306 |

默认 B=2,000 时，工作进程寿命峰值 RSS 约 29.8–29.9 MiB，由 Windows 上已有 psutil 的 peak_wset 获取；它包括导入，不包括父记录器及子进程，不是单独科学数组占用。表中的范围是三次观测最小/最大值，不是置信区间。完整 CLI 时间由外层测试者计时，包含启动和记录收尾；执行记录中的 wall_time_s 另保留其明确的父记录器计时范围。

这份代码的科学运算时间为 O(N0 + BN + B log B)，N0 是初始试次数，BN 对应重采样，B log B 对应排序；额外内存为 O(N0 + B)，还需计入 Python 对象及序列化开销。完整运行包含启动、记录、哈希和磁盘成本，在小数据上不能直接用 B 的倍数放大全部墙钟时间。日志捕获由文件描述符直接写盘，不把整份日志堆入父进程内存。

全部原始测量、各次日志/状态/配置/结果和源码哈希在 `evals/results/execution_validation_20260906/`；汇总为 measurements.json。测量之后仅修改了一个不改变执行含义的函数副作用说明，原测量源码快照保留；这不是 xiphos 测量，也不是实际大型研究的吞吐保证。本轮未重跑之前的 60 次模型生成实验，旧报告对应旧封存版本。

## 剩余范围

Windows 的完整示例、实际取消分支和资源获取经过测试；Linux/macOS 分支使用标准库 resource，但本轮未在那些系统重新执行。没有 GPU/分布式进程树资源测量。强杀父记录器、掉电或写入存储故障可能留下 running/unknown，规则要求保留证据而非伪造终态。新规范的模型遵循率尚未经新一批生成评测验证，不能由程序回归通过推断模型会稳定执行全部要求。
