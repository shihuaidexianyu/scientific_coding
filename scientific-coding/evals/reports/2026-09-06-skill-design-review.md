## 发现与处理

| 发现 | 修改 |
|---|---|
| 旧规则偏向“先检查再删减”，没有禁止初稿预装防御 | 主入口和五轮工作流明确先完成方法，第二轮再按 checks.md 判断候选检查 |
| artifact/view/统计指南把入口或边界当作必检理由 | 统一服从具体触发依据、可能性、后果、API 能力和复杂度收益判断；区分作者核验与运行检查 |
| 原生 API 已会报错，模板仍添加同义 guard | 函数模板用 statistics.mean，自然传播 StatisticsError，删除额外空列表检查 |
| 普通配置模板预装 requires_approval=false | 删除该字段；用户明确选择暂停时才引入对应设施 |
| 环境、时间、性能模板预填数值及 pass/accept | 改为 null、未运行/未评估及待采集说明；不放宽优化证据验证器 |
| 主入口、阶段指南、审计重复同套格式和流程 | 入口保留共同约束与路由，阶段引用统一格式，审计只说明核验职责 |
| 普通估计/核验被迫携带完整优化和 linter 手册 | 新 estimation.md 与 lint.md 分离阅读场景，按当前决定加载 |
| 集成示例容易被整体复制为默认框架 | 明确可选功能范围；保留已测运行代码，说明旧例未全面整改为最新格式规则 |

检查论证不要求逐项用户审批、概率表、证明日志或检查管理器。
没有数据时不编造发生率，“未知”不自动授权添加防御；极小概率内存偶发错误
不构成逐层扫描或重复计算的依据。已有代码先评估实际保护，不一概删除。
