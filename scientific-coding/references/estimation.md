# 运算时间与效率估计

普通科研代码交付只需阅读本文件；仅在实际优化时再读 [optimization.md](optimization.md)。

## 每次代码交付的耗时与效率估计

在代码之后用中文给出与任务规模相称的估计，不论用户是否请求性能优化。说明：

- 工作量与运行条件：样本/通道/时间点、重采样次数、文件大小等实际主导维度，CPU/GPU、可用内存、worker/线程数。未知项明确写出。
- 主要时间复杂度和内存复杂度，并解释这些量在本代码中对应什么。按真实循环、排序、求解和 I/O 推导；例如逐次处理 B 份长度 N 的重采样，并排序 B 个统计量，时间为 O(BN + B log B)，不能漏掉排序，也不能把 Python 对象内存等同于原始数值字节。
- 有依据的单次端到端耗时区间、峰值内存估计及瓶颈。写明是同环境实测、代表性小试验外推还是仅复杂度分析；链接实际运行记录。不能用编写代码耗时、单个核函数耗时或瞬时内存代替完整运算成本。
- 涉及批量时给出总成本和现实并行假设。理想近似 ceil(K/W) × T 仅适用于 K 个相近的独立任务、W 个可用 worker，实际还包括启动、调度、I/O/内存争用和长尾，不能默认 W 倍加速。

缺少硬件、数据规模或校准时仍交付复杂度与条件化估算，明确“目前无法可靠给出绝对耗时”。给出最小校准办法，不为填一个数字启动整批昂贵计算或阻塞已完成的代码。已有授权范围内，可用代表性小规模测量；记录冷/热启动、至少一个能反映扩展规律的工作量及不确定性。无依据时不给伪精确的秒数或固定误差百分比。

代码、数据量或并行策略变化后更新受影响估计；纯注释或排版改动可简述“计算路径未变，沿用某次测量”，无需重测。实际优化仍须执行 [optimization.md](optimization.md) 中的前后等价性与端到端实测；复杂度没有变化不等于运行时间绝对不变。

交付写法示例（符号示意，不能当成实测）：

> 运算成本：N 为保留试次数，B 为 bootstrap 次数；时间 O(BN + B log B)，额外内存 O(N + B)。目前没有目标机器测量，无法可靠报出分钟数。先在同一数据与环境测较小 B，单列读取/保存和重采样耗时，再按 B 外推并保留排序及启动开销；完整实测和日志路径在运行后补充。

普通运行的日志、资源与批量索引要求见 [execution.md](execution.md)。测量能力不足时保留 null 与原因，不伪造峰值或把估算写入实测字段。
