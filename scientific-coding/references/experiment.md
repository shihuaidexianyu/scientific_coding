# 实验组织与检查职责

新实验采用下面结构，名称按实际科学目的确定；已有项目仅在明确迁移时调整。

```text
project/
├── experiments/
│   └── amplitude_comparison/
│       ├── amplitude_comparison.md
│       ├── amplitude_comparison.toml
│       └── run_amplitude_comparison.py
└── stages/
    ├── preprocess.py
    └── estimate.py
```

## 参数与方法各有归属

- MD 写目的/假设、数据及样本单位、分组与筛选依据、实际阶段和分支、关键
  参数理由、预期产物及解释边界、运行命令和日志位置；不预写有利结果。
  具体取值以 TOML 为准，避免重复抄录。科学设计变化时更新对应说明。
- 同目录一份实验命名的 TOML 管理数据路径、可调科学参数、随机与运行参数。
  按用途分节，不再指向各 stage 的独立配置，不引入隐藏继承和多层覆盖。
- 专属编排 Python 写实际执行顺序、方法分支、参数分发和发布安排。允许
  少量清楚的调用重复；稳定科学操作才复用，方法不同可用专属 stage。
  不用通用 DAG、工厂或大量 mode 开关隐藏科学差别。
- stages/ 只实现具名科学步骤，不导入其他 stage 的实现或反向导入编排器。
  步骤交换有说明的数据；中间值无需都持久化，也不默认建立契约/哈希框架。

图表展示已计算的科学量，不在绘图辅助函数里隐藏筛选、拟合或推断。
同文件展示与计算可以共存，但以具名函数区分，保留实际结果来源。

编排从脚本位置定位默认 TOML，只读取解析一次。显式配置路径可以按启动
目录定位，但 TOML 内相对路径必须按选中 TOML 的目录解析，绝对路径保持。
不通过全局 chdir 修正路径。编排传具名参数或明确的阶段子集、已解析路径；
stage 不读取/接收总配置或全局上下文，仍可用传入路径读取实际科学数据。
若已有必要命令行覆盖，在编排中一次应用并记录实际值。

## 初稿不预装检查

先贯通原始方法，再判断候选检查：有什么可信触发场景、可能性依据及实际
后果，当前构造或原生 API 是否已经排除/暴露它，收益是否值得增加复杂度。
无依据就不加；未知概率不自动授权，不编造发生率。偶发内存损坏不是逐层
shape/finite/hash 检查的理由。已有保证有效时复用，不要求凑出一项检查。

普通 open、解析器和数值库错误自然传播。方法定义的筛选、分组、收敛和
算法分支仍属于业务；它们不是额外检查。只因外部文件或函数调用就新增
预检也不成立。作者离线测试和科学设计核验不转成每次运行的检查步骤。

## 必要检查放在实际编排的正确时点

```text
编排读取实际输入与配置 → 必要输入检查 → 业务变换
    → 接收实际中间数据 → 仅检查新受到影响的前提 → 依赖计算 / 正式发布
```

编排可在同文件用短小、具名的检查函数，失败抛错由已有外层记录；不将
整个 pipeline 套在逐层 if 中。stage 及其辅助调用链不含防御验证、检查
回调或装饰器；把 assert 改名 check_input() 或显式验证 API 参数不算迁出。
第三方库不可分离的内建错误处理不用重写。检查函数不偷偷筛选或修复数据。

配置检查后传入同一份实际值，不能让 stage 再读可能变化的文件。筛选后
样本量只在得到实际保留数据后、估计或发布前检查；原始样本量不能替代它。
若风险在 stage 中段，暴露有科学含义的函数和中间结果，由编排调用前半步、
检查、后半步，不必新增正式 stage。大数据可用已有分块或暂存路径，不为
检查复制全量数组、耗尽生成器或重跑随机计算。

已有 run() 混合计算、检查、发布时，先分离这些职责，再迁移必要检查；
不能只复制成两份，也不能等正式结果发布后补查。单独执行 stage 的命令
调用同一编排步骤，不绕过检查、不复制记录器、不让业务反向导入编排。
修旧代码先识别每个检查保护的事实，避免删除唯一必要保护。

## 验收

沿 MD → TOML → 编排 → stage 核对实际方法和参数。对新入口从不同启动
目录使用同一配置，确认路径一致；针对迁移检查的实际反例验证失败在依赖
计算和发布前发生、日志保留，正常结果及随机/消费顺序不变。
相关验证由作者完成，不增加运行时证明标志或审批表。需要查看检查调用
片段时见 [pipeline_boundary.md](../templates/pipeline_boundary.md)。
