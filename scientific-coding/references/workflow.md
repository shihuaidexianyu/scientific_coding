# 分轮撰写与中途协作

用户给出整个 plan 时，连续完成目标，按下列职责审视同一份代码。轮次是 agent 的工作方式；不向科学流水线增加循环、检查器或人工审批。准确性和可读性优先，可以投入更多推理和审阅，但每次返工应有具体问题。

## 五轮各自解决什么

| 轮次 | 工作 | 本轮完成的依据 |
|---|---|---|
| 实现 | 按 plan 贯通输入、各阶段和输出；保留关键科学理由、假设及数据结构草注 | 请求的行为已实现，关键计算可定位，缺失的科学决定已明确 |
| 简化 | 核对逻辑，删去重复检查、死代码、无意义包装和重复门控，整理线性计算顺序 | 每个保留的检查都有未被既有保证排除的具体错误；代码结构有助于读懂方法 |
| 说明 | 对照实际实现补全中文文件头、函数文档、语义块注释、关联 TOML 注释和数据说明；参数值未改的关联配置也需查看 | 调用处可由语言服务读取函数文档；本地给出参数、产物、嵌套结构、单位和逻辑，无须跳到另一函数才能看懂 |
| 格式 | agent 为本次语言编写并执行注释格式脚本，按需修正块前空行，对最终文件运行检查模式 | 实际运行成功，源码可解析，配置含义和字符串内容保持不变；最终检查已通过时无需再做无改动的修复 |
| 核验 | 联合审阅科学逻辑、可读性与注释真实性，运行与改动相关的测试和检查 | 发现的问题已解决或具体说明；证据对应交付的代码版本 |

先简化再补全注释，减少给冗余代码精装修后又删除的工作。实现时仍记录难以事后还原的科学理由，避免最后猜测作者意图。排版脚本只处理可机械判断的格式；不能证明注释正确或代码合理。

实现与修改由明确的负责人完成，避免多方同时覆盖。对完整 plan 或跨多个函数的说明/简化任务，在当前环境支持并允许 agent 分工时，让另一个 agent 完成最后的只读核验；先给它当前源码、关联配置和实际数据/测试证据，让它先读文件，再看作者的完成声明。小改动只做相应复核；没有独立 agent 时由当前 agent 重读最终文件，并如实说明核验范围。

核验者逐个对照函数签名与本地说明，确认输入和返回结构在本次调用处就能读懂；沿真实读写核对文件图，沿数据轴和计算核对单位、顺序及已有保证。格式器“执行成功”和“确实能识别缺空行”分开看。返回有具体位置和实现依据的问题，由负责人局部修复；改动后只复核受影响项。核验是自动撰写工作的最后一轮，不需要每轮换 agent、轮次审批、流程控制器或强制状态文件。

## 发现问题后局部返工

根据问题返回必要的工作，而不是重新生成整个 plan：

- 缺少注释块前空行：修正格式脚本或覆盖范围，重新格式化并验证解析与内容保持。
- 注释没有解释参数单位：修正文档，复核其与实现一致，再处理受影响文件的格式。
- 同一输入被重复验证：先确定上游保证仍有效，移除重复检查，更新对应解释并验证受影响行为。
- 筛选、分组或统计方法改变：修正实现，重新审视下游数据语义和推断前提，更新说明、格式及相关测试；历史结果保留，新运行单独保存。

没有新改动、失败或未解决疑点时，不重复已经通过的检查。小修复直接做适用的工作，不为凑齐五轮重写无关部分。

## 用户在审查中途提问或修改代码

先识别用户消息的作用：

| 情况 | 处理 |
|---|---|
| 只问含义、依据或进展 | 基于当前代码先回答，再继续原任务；提问本身不触发整轮重做 |
| 新增或修正要求 | 更新目标及受影响范围，保留仍适用的既有决定和已完成工作 |
| 用户手动改了代码或配置 | 以当前文件为工作起点，核对差异和意图，更新相关说明与验证 |
| 用户明确要求暂停、只讨论或换目标 | 按要求停止相关执行，保留当前成果与续接位置 |

每次恢复写入前，重读即将修改的相关文件，核对自上次查看以来的变化。补丁上下文不匹配时重新读文件再合并，不把旧的整文件副本写回去。这是编辑期间保护共同工作的措施，不得转化为科学程序中的重复检查。

用户的改动不自动视为错误，也不自动视为已经验证正确。能从对话与代码确定意图时直接衔接；出现实质冲突时，指出具体位置、不同解释及其影响，仅询问无法自行确定的决定。只暂停依赖该决定的部分，其余独立工作继续。

例如，用户将排除条件由 `amplitude_uv < floor` 改成 `amplitude_uv <= floor`：

1. 明确等于阈值的试次现在也被排除，保留这项有意修改。
2. 同步更新阈值 TOML、筛选注释、函数文档和数据说明中的边界约定。
3. 复核保留样本、排除记录、组样本量及依赖它们的统计结果；运行相关边界与科学行为检查。
4. 格式化受影响文件，再交付与当前版本对应的证据。无关的读取实现无需重新编写。

## 续接记录与证据

长任务只需在现有计划或简短工作笔记中保留目标、当前轮次、受影响文件、未解决问题及适用的检查结果。不要引入逐函数“已验证”标志、证明账本或每轮完成报告。

并行或长时间运行的检查开始后若代码变化，先判断结果是否仍适用。受影响的旧检查仅能说明它所检查的版本；针对新版本重跑必要部分。依赖旧代码或旧参数生成的科学结果也不能冒充新版本产物。最终清楚说明实际改动、相关验证及仍未覆盖的限制。
