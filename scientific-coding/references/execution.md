# 运行记录与成本交付

每个实际科研运行在业务执行前建立一次外层记录，复用已有调度/日志设施。
记录器不参与科学计算，不偷偷验证或修复数据。较小项目保持简单，不默认
复制高级产物协议、检查点或审批系统。

## 每次尝试保留的证据

| 内容 | 要求 |
|---|---|
| 来源 | 实际输入的角色和哈希/版本，实际生效配置及覆盖，源码版本/哈希（含未提交修改），环境、依赖与硬件；复用有效绑定，不重复散列 |
| 科学身份 | 随机种子及实现，必要的划分/置换身份，样本数量与单位、排除 ID/原因、拆分/聚合映射及权重 |
| 输出与诊断 | 完整 stdout、stderr、异常堆栈，包含子进程输出；终端显示不能替代文件，注明编码和路径 |
| 生命周期 | 唯一运行编号，实际命令/目录，UTC 起止时刻，单调时钟耗时，真实状态/退出码，最后阶段与主要阶段耗时 |
| 资源 | 可获得的 CPU 时间、峰值 RAM，涉及 GPU 时的 VRAM；注明进程/进程树、采样或累计等口径 |
| 结果 | 本次输出位置和是否完整；执行成功不等于统计显著，未产生结果不填成功 |

配置解析和输入读取之前就开始记录，早期失败也有日志。新运行使用新目录，
保留旧结果及失败证据；必要的结果检查通过后才正式发布，失败暂存不冒充
完整产物。诊断不因清理本次未发布载荷而丢失，不修改历史结果补说明。

成功、失败、取消、用户指定暂停分别记录。异常记录后正常传播；实际子进程
退出码或调度状态是依据，启动失败另记，不伪造子进程退出码。强杀/掉电
可能无法写终态，保留 running/unknown 与已有证据，不猜造结束时间。
取消只作用于本次所属进程树或调度任务，不能只结束记录器遗留计算。

一个实验尝试共用一份外层记录；阶段只由编排补充时间与状态。独立 stage
命令复用同一执行路径；普通业务函数和测试不各套运行器。不记录凭据。

批量运行的索引关联所有尝试，包括失败、取消、重试：实验及运行编号、
配置/参数绑定、状态/退出码、起止/耗时/资源摘要、日志/记录/结果路径。
沿用现有格式；并行时独立条目或适当同步，不能丢记录或把正在写的结果标完整。

## 测量和交付估计

测不到的资源填 null/unknown 并解释，不把未知 RAM 写 0。墙钟、CPU、Python
分配、RSS、GPU allocated/reserved 是不同口径；并发阶段不能直接相加。
说明是否覆盖子进程，共享内存是否重复计数。优先已有工具，不默认逐行 profiling。

代码或计算参数交付后，用中文说明工作量 N/B 等含义、时间和额外内存复杂度、
目标硬件/worker、主要瓶颈与耗时依据。区分已有实测、外推和未知，不编造
秒数、百分比或加速比；说明最小校准方法，不为填数启动整批昂贵实验。
批量估计同时说明单次与整批耗时/资源成本，考虑实际 worker、争用、队列和
长尾任务，不能简单把单次时间除以申请的并行数。
纯注释改动可沿用仍适用的证据；方法或并行变化后更新受影响估计。

实际运行后报告实测与日志位置。新增运行机制只用相关成功、早期失败、重跑
保留和并发反例验证一次；不让这些自测进入科学运行流程。
优化/断点恢复等明确任务再读取 [extensions.md](extensions.md)。
