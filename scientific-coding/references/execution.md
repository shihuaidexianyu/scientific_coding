# 运行记录、失败诊断与批量实验

这些是科研运行的默认交付要求，普通运行也适用；性能优化的前后对照另见 [optimization.md](optimization.md)。记录工作放在入口、编排器或已有调度系统，不在每个数学函数和循环中添加日志包装、重复校验或审批。

撰写时先完成原始科学逻辑，再在交付运行前接入记录边界。记录实际输出、
时间和异常不等于审查数据；不能借日志功能加入预检、异常吞噬或自动修复。
拟增加的运行检查统一服从 [checks.md](checks.md)。小项目可用一个外层
启动函数或已有工具，不必复制集成示例的完整产物、暂停和恢复设施。

## 每次尝试留下什么

| 内容 | 必须保留的信息 |
|---|---|
| 实际来源 | 输入角色、路径和哈希/版本，有效配置及覆盖项，包含未提交修改的源码版本/哈希，环境、依赖与硬件；复用已有产物绑定，不重复散列已绑定数据 |
| 随机与样本 | 随机种子及实现/依赖，必要的划分或置换身份；样本数量与单位，排除 ID/原因及拆分聚合映射；见 [artifact.md](artifact.md) |
| 完整日志 | 保存 stdout、stderr 和完整异常堆栈，包含子进程的实际输出；可以合并为 UTF-8 run.log 或分别保存，明确编码和路径。终端显示不能代替落盘，不用最后几行或成功摘要冒充完整日志 |
| 运行生命周期 | 唯一 attempt/run ID、实际命令及工作目录、UTC 起止时间、单调时钟经过秒数、执行状态、实际退出码、最后进入/完成的阶段和错误位置 |
| 资源与阶段耗时 | 整体墙钟时间、可获取的 CPU 时间、主要阶段时间、峰值 RAM；涉及 GPU 时记录 VRAM。注明进程/进程树/节点范围、采样周期和统计口径 |
| 结果 | 结果路径及来源绑定，明确完整、部分或尚未产生；代码执行成功与统计结果是否显著分别表示 |

已有记录可通过明确路径关联，不要求在每个 JSON 重复整份来源或每层重查。避免记录凭据。提供一条可复制的运行命令和读取日志/元数据的方法；文件名可以沿用项目约定。

## 状态与失败

执行边界在启动业务代码、解析科学配置和读取数据之前创建独立尝试目录，写入 running 状态并打开日志；这些早期步骤失败也要留下记录。每次重跑用新编号，保留此前所有结果和诊断。正常完成、失败、主动取消和用户指定暂停必须可区分。未知信息用 null/unknown 并附原因，不能把未采集的内存写为 0，也不能给尚未结束的运行填成功或退出码 0。

一个顶层尝试共用一份记录。内部阶段只补充当前阶段和耗时，不各自再套启动器；阶段被单独启动时才创建自己的尝试。直接数值函数调用或单元测试由所属执行/测试入口负责记录，不给每个函数加日志状态对象。

在可处理的退出路径记录结束时间、耗时和退出码，传播原失败而不是吞掉异常；从进程实际返回值或调度器获取退出状态。启动失败尚无子进程退出码，应另记 launch_failed。强杀、掉电或机器不可达可能无法写最后一条记录，此时保留 running/unknown、已有日志和调度证据，恢复核实时标明“结束未确认”，不猜造时间或退出码。批量任务取消不能只结束记录器而遗留其计算进程；使用所属进程组或调度器的取消机制。

失败前产生的诊断和已完成阶段仍保留。只清理本次未发布的临时科学载荷，不删除整个尝试目录或失败日志。日志/状态文件会持续变化，放在已封存科学产物之外；不能给一个已哈希封存的文件继续追加输出。完整科学产物仍按 [artifact.md](artifact.md) 暂存后发布。

## 资源测量口径

墙钟时间包含计算、I/O、等待和启动开销；CPU 秒数可因并行大于墙钟秒数。阶段耗时注明覆盖读取、计算还是保存，不能把写元数据的瞬间当成阶段起点。嵌套或并发阶段的时间不能直接相加当作总耗时。

优先复用调度器或现有监测。采样峰值只是观察到的峰值，可能遗漏短峰；累计进程寿命的峰值不能说成本次函数增量，Python 分配器内存不能冒充总 RSS。使用 GPU 时说明 allocated/reserved 或设备占用口径，并在需要测量完成时间时处理异步执行。多进程注明是否计入子进程、共享内存是否可能重复计数。

无法采集某项时记录 null 和具体原因，说明可行的采集办法；不为收集普通运行记录安装庞大监测框架或启用高开销逐行 profiling。新增依赖须符合项目约定。运行结束后用实测值补充交付估算，保留原估算作为估算。

## 批量索引

批量、重复或对照实验都提供可按条件/状态查询的索引：experiment ID、attempt ID、有效配置或绑定路径、状态、退出码、起止时间、耗时、资源摘要、日志与结果路径。失败和取消也有条目；重试关联原 experiment ID，却产生新的 attempt ID。可用已有数据库、CSV/JSONL 或每次一个 JSON 的索引目录。

并行写入必须避免丢行、截断或互相覆盖；例如每次尝试独立写一份索引条目，最后按需汇总。不为小批次新建调度器。若输出仍在写入，索引不能宣称完整；总耗时估计还要考虑实际 worker 数、争用和队列等待。

## 示例与验收

[最小流水线](../examples/minimal_pipeline/README.md) 展示启动边界的日志、尝试记录和独立索引。JSON 结构参考 [execution_record.json](../templates/execution_record.json) 与 [runtime.json](../templates/runtime.json)；示意中的 null 需要实测或保留未采集原因，不照抄示例测量值。

改动记录机制时，以隔离任务核验：成功有完整日志和正确退出码；失败保留 stdout/stderr/堆栈和阶段，返回非零；重跑不改旧文件；并发索引完整；暂停不会标成整个研究完成。对已有机制只验证此次变更涉及的部分，不每次运行重复这套自测。
